# 画会移动的线 & 消除残影

> 问题：**线每帧都在动，怎么擦掉上一次的？**
>
> 先说结论：**裸帧缓冲没有"背景重绘"，谁画的谁擦。**
> 下面 5 种方法，从最简单到最省事排列，按场合选一个。

> ⚠ **本文第 7 章的例子用到 `g_adc_code` / `g_adc_mv` / `ADC_ToY()`**，
> 这三个是 `ADC到屏幕使用说明.md` 里让你新建的（工程里现在还没有）。
> 如果你只是想知道"怎么画会动的线"，把 `ADC_ToY(...)` 换成任意算出 y 的表达式即可，
> 擦除逻辑和 ADC 完全无关。

---

## 0. 为什么会有残影

这个工程的帧缓冲是**单缓冲**，`ui_draw()` 每帧只是往同一块内存上覆盖像素。
没有任何东西会自动"重置屏幕"。

所以：

```c
/* 第 1 帧：线在 y=100 */
ui_hline(20, 460, 100, C_CH1);

/* 第 2 帧：线在 y=120 */
ui_hline(20, 460, 120, C_CH1);
/*  ↑ y=100 那条没人管，一直在屏幕上 -> 残影 */
```

屏幕会变成一片越来越密的线。

**唯一正确的思路**：画新线之前，先把旧线那块恢复成"背景该有的样子"。

---

## 1. 方法一：用纯色盖掉（最简单，够用 90% 的场合）

如果你的线画在**纯色背景**上，直接拿背景色盖：

```c
#define X0  20
#define X1  460

static void ui_main(void)
{
    static int y_old = -1;              /* ★ 必须 static */
    int y = 计算新位置();

    /* ① 擦：用背景色把旧线盖掉 */
    if (y_old >= 0)
        ui_hline(X0, X1, y_old, C_BG);

    /* ② 画：画新线 */
    ui_hline(X0, X1, y, C_CH1);

    /* ③ 记住，下一帧用 */
    y_old = y;
}
```

**要点**：

| 要点 | 说明 |
|---|---|
| `y_old` 必须 `static` | 普通局部变量每帧重置成 -1，就永远不擦了 |
| 先擦后画 | 顺序反了等于没擦 |
| 最后才更新 `y_old` | 更新早了，擦的就是新位置 |
| `y_old >= 0` 判断 | 第一帧没有"旧线"，别擦 |

**这是最常用的方法**，只要你的线下面没有网格/图片，就够用。

### 1.1 如果线是斜的 / 竖直的

同样的道理，只是要用对应的图元：

```c
/* 斜线：记下旧的两个端点 */
static int x0_old = -1, y0_old, x1_old, y1_old;

if (x0_old >= 0)
    ui_line(x0_old, y0_old, x1_old, y1_old, C_BG);   /* 擦 */
ui_line(x0, y0, x1, y1, C_CH1);                       /* 画 */
x0_old = x0; y0_old = y0; x1_old = x1; y1_old = y1;
```

```c
/* 竖线：记旧的 x */
static int x_old = -1;

if (x_old >= 0)
    ui_vline(x_old, Y0, Y1, C_BG);
ui_vline(x, Y0, Y1, C_CH1);
x_old = x;
```

```c
/* 粗线：`thickness` 要一样，否则擦不干净 */
static int y_old = -1;

if (y_old >= 0)
    ui_line_thick(X0, y_old, X1, y_old, 5, C_BG);   /* 擦，粗细一致 */
ui_line_thick(X0, y, X1, y, 5, C_CH1);
y_old = y;
```

> ⚠ **粗线擦的时候 `thickness` 必须和画的时候一模一样**。
> 画用 5 擦用 3，边缘会留两条毛边。

### 1.2 如果线下面有网格（★ 常见坑）

用 `C_BG` 擦会把网格线一起擦断，留下一道"白疤"。

**错的样子**：

```
────────────────────────  ← 网格
████████████████████████  ← 你的线
────────────────────────
        ↓ 用 C_BG 擦
────────────────────────
                          ← 网格被擦掉了！一道黑带
────────────────────────
```

**解法 1：线画满整行，擦完把网格补回来**

```c
if (y_old >= 0)
{
    ui_hline(X0, X1, y_old, C_BG);          /* 擦 */
    /* 如果 y_old 正好压在网格线上，补回来 */
}
```

这个判断很麻烦，不推荐。

**解法 2：把线画在专门的"背景干净"区域**

比如把状态栏（y 0~19）或工具条（y 227~271）当指示区，那里是纯色。
或者自己用 `ui_fill()` 先铺一块纯色底板，线只在底板里动：

```c
/* 铺一块纯色底板（只需一次） */
static int inited;
if (!inited)
{
    inited = 1;
    ui_fill(20, 40, 440, 120, 0x0841);       /* 深一点的纯色 */
    ui_rect(20, 40, 440, 120, C_EDGE);
}

/* 线只在底板内部移动，擦用底板色 */
if (y_old >= 0) ui_hline(20, 460, y_old, 0x0841);
ui_hline(20, 460, y, C_CH1);
y_old = y;
```

**这是最稳的做法**，推荐。

**解法 3：用 `bg_at()` 精确还原（下一节）**

## 2. 方法二：`bg_at()` 精确还原（线必穿过网格时用）

`ui_render.c` 内部有一个 `bg_at(x, y)`，能算出"这个像素如果没有波形，应该是什么颜色"，
它会正确还原网格、触发线、读数面板边框。

不过它是 `static` 的，**应用层调不到**。有两个选择：

### 2.1 方法 2A：干脆不自己擦，让框架擦（推荐）

如果你的线画在**波形区（y 20~226）**，而且你走的是框架的正常流程，
`ui_draw()` 内部已经在帮你擦了 —— 它每帧会擦掉上一帧的轨迹。

```c
/* ui_render.c:1076 附近，ui_draw() 内部 */
if (s_prev_valid)
    擦上一帧的轨迹();        /* 用 bg_at() 还原成网格 */
```

但**这个机制只擦它自己画的波形轨迹**，你通过 `ui_set_custom()` 画的东西它不知道。

所以：

> **把"会动的线"作为波形数据喂给 `ui_draw()`**，而不是自己用 `ui_hline` 画。
> 这样擦除、网格还原全部由框架负责，你一行擦除代码都不用写。

做法是把数据塞进 `wave_window_t`：

```c
/* main.c 里造窗口数据 */
static wave_window_t w;

w.n     = NPT;
w.dt_ns = ui_scan_div_ns(g_ui.scan) / PPD;
w.ch_mask = CHM_CH1;              /* 开 CH1 */

for (i = 0; i < NPT; i++)
    w.ch1[i] = 你的数据[i];        /* 0..4095 */

ui_draw(&w);                      /* 框架负责画 + 擦 */
```

**但注意**：这样画的是"波形"，形状由数据决定，不是一条自由的横线。
如果你要的是"一根随 ADC 上下移动的横线"，就把所有点填成同一个值：

```c
uint16_t v = ADC_GetAvg();        /* 同一个值 */

for (i = 0; i < NPT; i++)
    w.ch1[i] = v;                 /* 500 个点全一样 -> 一条横线 */

ui_draw(&w);                      /* 一条会上下移动的横线，自动擦除 */
```

<details>
<summary>点开看：这个方案的关键前提</summary>

- 需要 `g_ui.ch_mask = CHM_CH1`（`main.c` 里现在是 `0`，要改）
- 需要 `g_ui.trig_on` 等设置合理
- 需要 `ui_chrome_enable(1)`（框架要开着，才能画网格和波形区）
- 线限制在模拟通道区（y 20~175），不能在整屏任意位置

</details>

### 2.2 方法 2B：把 `bg_at` 暴露出来（要改库）

如果一定要在**任意位置**画线又要精确还原网格，就得改 `ui_render.c`：

```c
/* ---- ui_render.c：加一个公开函数 ---- */
uint16_t ui_bg_at(int x, int y)
{
    if (x < 0 || x >= (int)SCR_W || y < 0 || y >= (int)SCR_H)
        return C_BG;
    return bg_at(x, y);
}
```

```c
/* ---- ui_render.h：加声明 ---- */
uint16_t ui_bg_at(int x, int y);
```

然后用它来擦：

```c
/* 擦掉 y_old 那一整行，逐像素还原正确背景 */
for (x = X0; x <= X1; x++)
    ui_px(x, y_old, ui_bg_at(x, y_old));

/* 画新的一行 */
ui_hline(X0, X1, y, C_CH1);
y_old = y;
```

**代价**：擦一行 440 像素要 440 次 `ui_px` + 440 次 `ui_bg_at` 查表。
216 MHz 下大约 **0.1~0.2 ms**，25fps 完全够。

> 改库有风险（下次 CubeMX 不会覆盖，但你可能会忘）。
> 如果只是考试/作业，用方法一或方法三，别改库。

## 3. 方法三：整块重画（最简单粗暴，也最不容易错）

不记 `y_old`，每帧把**整块区域清掉再重画**：

```c
static void ui_main(void)
{
    int y = 计算新位置();

    /* ① 整块区域刷成背景（一次搞定，不用记旧位置）*/
    ui_fill(X0, Y0, X1 - X0, Y1 - Y0, C_BG);

    /* ② 把这块里的静态内容重新画一遍（网格、刻度、文字）*/
    /* ... 如果有的话 ... */

    /* ③ 画线 */
    ui_hline(X0, X1, y, C_CH1);
}
```

**优点**：

- 不用记任何 `y_old`，代码最简单
- 永远不会漏擦（哪怕你画了 10 条线）

**缺点**：

- 每帧重画整块，有闪烁（`ui_fill` 到重新画完之间屏幕是空的）
- 静态内容（网格、刻度）要跟着一起重画

**怎么减轻闪烁**：

| 技巧 | 说明 |
|---|---|
| 区域尽量小 | 只清线会经过的那几条像素高，而不是整屏 |
| 不要每帧都清 | 数据没变就不清（见方法四的缓存思路） |
| 用 `ui_field` 的思路 | 记住上次的值，没变跳过 |

> **考试/作业首选这个方法**，因为写起来最不容易出 bug，速度也够。

## 4. 方法四：只擦"变化的那一段"（最省事，推荐）

不擦整行，只擦**新旧两条线之间**那一段：

```c
static int y_old = -1;

int y = 计算新位置();
int lo, hi;

if (y_old >= 0 && y_old != y)
{
    lo = (y < y_old) ? y : y_old;          /* 较小值 */
    hi = (y < y_old) ? y_old : y;          /* 较大值 */

    /* 只擦 lo+1 .. hi 这几行（原来线所在的行会被下面重画覆盖）*/
    for (i = lo; i <= hi; i++)
        ui_hline(X0, X1, i, C_BG);
}

ui_hline(X0, X1, y, C_CH1);
y_old = y;
```

严格说这个方法**擦的比需要的多**（把中间全擦了），但：

- 代码简单，不会算错
- 数据变化很小时（ADC 抖动几 LSB），只擦几行，几乎不闪
- 数据大幅跳变时擦得多，但那时本来就要重画

**这实际上是方法一和整块重画的折中，最好用。**

### 4.1 更严格：只擦旧行，不擦中间

```c
if (y_old >= 0 && y_old != y)
    ui_hline(X0, X1, y_old, C_BG);        /* 只擦旧行 */

ui_hline(X0, X1, y, C_CH1);
y_old = y;
```

这就是方法一。两者的区别：

| | 只擦旧行（方法一） | 擦整个区间（方法四） |
|---|---|---|
| 擦的像素 | 440 个 | 最多 `\|y-y_old\| × 440` |
| 跳变时会怎样 | 中间快速划过的地方可能留断点 | 干净 |
| 速度 | 最快 | 稍慢 |

**数据变化慢（ADC、电位器）用方法一；变化快（跳变、动画）用方法四。**

## 5. 方法五：双缓冲（本板不能用）

理论上最彻底：画到后台缓冲，画完一次切过去，永远不闪也不残影。

```c
void ui_use_sdram(void);      /* 工程里有，但不要调 */
```

**这个板子用不了**，因为：

1. 双缓冲需要两块 480×272×2 = 261 KB 的缓冲
2. 内部 SRAM 总共只有 320 KB，放不下一块大的再放第二块
3. SDRAM（`0xC0000000`）初始化没通，一访问就死机（详见 `如何使用这个工程.md`）

所以单缓冲 + 手动擦除是**唯一选择**。

## 6. 怎么选：一张表

| 你的情况 | 用哪个方法 |
|---|---|
| 线在**纯色背景**上移动 | **方法一**（最常用） |
| 线下面有**网格**，且不能改库 | **方法二 2A**（喂给 `ui_draw`）或**方法三**（铺纯色底板） |
| 线在**任意位置**，要精确还原网格 | 方法二 2B（改库暴露 `bg_at`） |
| 数据**跳变快**、线条会瞬移 | **方法四**（擦整个区间） |
| **不确定**、想先跑通 | **方法三**（整块重画） |
| 想要**完全不闪** | 本板做不到，只能用 `ui_field` 的思路减少重画 |

## 7. 完整可跑例子

### 7.1 ADC 控制的横线（纯色底板，不闪）

```c
#include "app_data.h"
#include "adc_read.h"

#define BX   20          /* 底板左上角 */
#define BY   40
#define BW   440
#define BH   120
#define BCOL 0x0841      /* 底板色，深灰 */

static void ui_main(void)
{
    static int inited;
    static int y_old = -1;
    int y;

    /* ---- ① 底板 + 边框，只画一次 ---- */
    if (!inited)
    {
        inited = 1;
        ui_fill(0, 0, 480, 272, C_BG);
        ui_text16(20, 8, "ADC LEVEL", C_WHITE, UI_BG_NONE);
        ui_fill (BX, BY, BW, BH, BCOL);        /* 纯色底板 */
        ui_rect (BX, BY, BW, BH, C_EDGE);
    }

    /* ---- ② 算新位置 ---- */
    y = ADC_ToY(g_adc_code, BY + 2, BY + BH - 3);

    /* ---- ③ 擦旧 + 画新（底色用 BCOL，不是 C_BG）---- */
    if (y_old >= 0 && y_old != y)
        ui_hline(BX + 1, BX + BW - 2, y_old, BCOL);

    ui_hline(BX + 1, BX + BW - 2, y, C_CH1);
    ui_line_thick(BX + 1, y, BX + 7, y, 7, C_CH1);   /* 指示头 */

    y_old = y;

    /* ---- ④ 数值 ---- */
    {
        char buf[24], *p = buf;
        p = ui_fix(p, g_adc_mv, 3);
        p = ui_str(p, " V");
        ui_field(0, 20, 176, 200, 18, buf, C_CH1, C_BG);
    }
}
```

**为什么这个不闪**：

- 底板是纯色 → 擦用 `BCOL` 不会破坏任何东西
- `y_old != y` 判断 → 值没变时一个像素都不动
- 只擦一行 440 像素 → 快

### 7.2 竖直滚动指示线

```c
static void ui_main(void)
{
    static int x_old = -1;
    int x;

    /* 顶部一条刻度尺 */
    static int inited;
    if (!inited)
    {
        inited = 1;
        ui_fill(0, 0, 480, 272, C_BG);
        ui_hline(20, 460, 30, C_EDGE);
    }

    x = 20 + (int)((uint32_t)g_adc_code * 440u / 4095u);   /* 20..460 */

    if (x_old >= 0 && x_old != x)
        ui_vline(x_old, 20, 40, C_BG);         /* 擦旧的竖线 */

    ui_vline(x, 20, 40, C_CH2);                /* 画新的 */
    x_old = x;
}
```

### 7.3 多条线同时动

每条线各自记旧的：

```c
#define NL 3
static int s_yold[NL] = { -1, -1, -1 };       /* 数组记 3 条线的旧位置 */

static void ui_main(void)
{
    int i, y;

    for (i = 0; i < NL; i++)
    {
        y = 计算第 i 条线的位置(i);

        if (s_yold[i] >= 0 && s_yold[i] != y)
            ui_hline(20, 460, s_yold[i], C_BG);

        ui_hline(20, 460, y, 颜色[i]);
        s_yold[i] = y;
    }
}
```

## 8. 常见问题

| 现象 | 原因 | 解法 |
|---|---|---|
| **线越画越多，一片** | 完全没擦 | 记 `y_old`，画前先擦 |
| **擦不动 / 看不出差别** | `y_old` 不是 `static` | 加 `static` |
| **只擦掉一部分，有断点** | 擦的时候 `thickness` 和画的不一样 | 粗细必须一致 |
| **线下面出现一道黑带** | 用 `C_BG` 擦了网格 | 用纯色底板（方法三），或 `bg_at`（方法二） |
| **数据不变时也在闪** | 每帧无条件擦+画 | 加 `y_old != y` 判断 |
| **偶发残留一个点** | 位置算出来越界了 | `ADC_ToY` 内部有夹取，自己算要 clamp |
| **擦完画完还是闪** | 整块重画，中间亮了 | 方法四（只擦变化区间），或铺底板 |
| **`ui_fill` 清屏后更乱** | 用了 `ui_fill` 而不是 `ui_clear` | 清屏用 `ui_clear`（`ui_fill` 不清内部缓存） |

### 一个特殊的坑：`ui_clear()` vs `ui_fill()`

```c
ui_fill(0, 0, 480, 272, C_BG);   /* ⚠ 只把像素刷黑 */
ui_clear(C_BG);                  /* ✅ 刷黑 + 清轨迹记录 + 清 ui_field 缓存 */
```

用 `ui_fill` 清整屏，下一帧框架会拿**上一帧的轨迹**去"擦"，在干净的屏上画回一堆网格碎片。
**清整屏一定用 `ui_clear()`。** 只清一小块区域用 `ui_fill` 没问题。

## 9. 一句话

```c
static int y_old = -1;                      /* ① 记住旧位置，必须 static */

int y = 算新位置();

if (y_old >= 0 && y_old != y)               /* ② 变了才擦，用【背景色】擦 */
    ui_hline(X0, X1, y_old, 背景色);

ui_hline(X0, X1, y, C_CH1);                 /* ③ 画新的 */

y_old = y;                                  /* ④ 最后才更新 */
```

**三句话**：

1. **谁画的谁擦** —— 没有自动清屏
2. **擦用什么颜色画的，就用什么颜色擦** —— 纯色底板用底板色，网格区用 `bg_at`
3. **值没变就别动** —— 加 `y_old != y` 判断，能消掉 90% 的闪
