# 通信协议说明（显示端 ↔ 采集端）

> 这份文档要**和采集端同学共同确认**，设计报告里也要写进去（任务书注意事项第 2 条）。

---

## 一、物理层

| 项目 | 显示端（本端） |
|---|---|
| 串口 | **USART6** |
| 引脚 | **PG14 = TX，PG9 = RX**（CubeMX 里 AF8）|
| 波特率 | **921600**（`drv_uart.h` 里的 `DRV_UART_BAUD_DEFAULT`）|
| 格式 | 8 数据位 / 无校验 / 1 停止位 |
| 接线 | 本端 TX → 对方 RX，本端 RX ← 对方 TX，**GND 必须共地** |

> ⚠ **注意引脚**：CubeMX 配的是 PG14/PG9，不是 Arduino D0/D1（PC6/PC7）。
> 如果打算用 Arduino 座子接线，需要在 CubeMX 里把 USART6 改到 PC6/PC7 再重新生成。

**为什么用 921600**：一帧 500 点约 2.5 KB，20 fps 需要 50 KB/s。
115200 只有 11.5 KB/s，远远不够；921600 约 92 KB/s，够用。

## 二、帧格式

所有多字节字段都是**小端**（低字节在前）。

```
+------+------+------+--------+-----------+--------+
| 0xA5 | 0x5A | TYPE |  LEN   |  PAYLOAD  | CRC16  |
+------+------+------+--------+-----------+--------+
   1B     1B     1B     2B       LEN B       2B
```

| 字段 | 说明 |
|---|---|
| 帧头 | 固定 `0xA5 0x5A` |
| TYPE | 帧类型，见下表 |
| LEN | PAYLOAD 的字节数（不含帧头/类型/长度/CRC）|
| PAYLOAD | 载荷 |
| CRC16 | 对 **TYPE + LEN + PAYLOAD** 计算 |

**CRC 参数**：CRC-16/CCITT，多项式 `0x1021`，初值 `0xFFFF`，输入输出都不反转。

**总帧长** = `7 + LEN`

## 三、帧类型

### 采集端 → 显示端

#### `0x01` DATA —— 波形数据

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `n` | u16 | 点数（本工程 500）|
| 2 | `dt_ns` | u32 | 采样间隔，纳秒 |
| 6 | `scan` | u8 | 档位 0..4 |
| 7 | `ch_mask` | u8 | 通道掩码 |
| 8 | `trig_status` | u8 | 触发状态位 |
| 9 | `ch1[n]` | u16[n] | CH1，12 位码值 0..4095 |
| 9+2n | `ch2[n]` | u16[n] | CH2 |
| 9+4n | `dig[n]` | u8[n] | 低 3 位 = D1/D2/D3 |

- `ch_mask`：bit0=CH1 bit1=CH2 bit2=D1 bit3=D2 bit4=D3
- `trig_status`：bit0=已触发 bit1=AUTO bit2=ARMED bit3=窗口内
- n=500 时 LEN = 9 + 1000 + 1000 + 500 = **2509**

#### `0x02` HEARTBEAT —— 心跳（可选）

| 偏移 | 字段 | 类型 |
|---|---|---|
| 0 | `status` | u8 |

### 显示端 → 采集端

| TYPE | 名称 | PAYLOAD |
|---|---|---|
| `0x81` | CMD_SCAN | `scan` u8 |
| `0x82` | CMD_CHANNEL | `ch_mask` u8 |
| `0x83` | CMD_SQW | `on` u8, `freq` u32, `duty` u8 |
| `0x84` | CMD_TRIG | `on` u8, `src` u8, `edge` u8, `level` u16, `mode` u8, `pos` u8 |
| `0x85` | CMD_RUN | `run` u8 |

- `edge`：0 = 上升沿，1 = 下降沿
- `src`：0=CH1 1=CH2 2=D1 3=D2 4=D3 5=自由运行
- `mode`：0=AUTO 1=NORMAL 2=SINGLE
- `pos`：触发点在窗口中的位置，百分比 0..100
- `freq`：100..10000 Hz
- `duty`：1..99 %

## 四、代码在哪一层

| 文件 | 层 | 职责 |
|---|---|---|
| `Drv/drv_uart.c/.h` | Drv | USART6 + DMA 收 + 空闲中断，只搬字节，不懂协议 |
| `App/app_proto.c/.h` | App | 拆帧、CRC 校验、组帧、DATA 载荷解析 |
| `App/app_link.c/.h` | App | 收数据→更新 `wave_window_t`、统计帧数/丢帧/CRC/帧率、下发命令 |

调用链：

```
app_task()
  └── app_link_poll()              每轮收一次
        ├── drv_uart_read()        从驱动的软件队列取一段字节
        ├── proto_feed()           找帧头、校验 CRC、解出一帧
        ├── proto_parse_data()     把载荷解成 wave_window_t
        └── 更新 g_ui.fps_x10 / frame_count / ndrop / crc_err
  └── app_link_get_window(&w)      取最近一窗数据
        有数据 → 直接画
        无数据 → app_ui_fill() 造仿真波形（便于单独调显示端）
```

命令下发：

```
工具条按钮 / 菜单改动
  └── app_link_cmd_xxx()
        └── proto_build_cmd_xxx()   组帧
              └── drv_uart_send()   发出去
```

## 五、调试方法

1. **看链路有没有数据**：`drv_uart_rx_total()` 返回值会一直涨说明在收
2. **看状态栏**：`frame_count` 和 `fps` 有数字说明解析成功；`D`/`E` 是丢帧和 CRC 错误
3. **没有采集端时**：程序会自动用仿真波形，界面功能仍可调试
4. **连线检查**：TX/RX 要交叉，共地；先降波特率到 115200 排除干扰再提速

## 六、待和采集端确认的点

- [ ] 串口波特率是否 921600（如果对方跑不了，可以降到 460800，但帧率会受限）
- [ ] 采样点数固定 500 还是可变
- [ ] 采样数据用 16 位还是打包成 12 位（打包能省 1/4 带宽，但解析麻烦）
- [ ] 是否需要 ACK / 重传
- [ ] 心跳帧要不要做
- [ ] 采集端是否自己产生时间戳和档位，还是显示端下发后回读
